## Intended release contents

The export includes root package/lock/toolchain files, the root README/license/submission draft, Expo application source and named icons/font assets, four Python service packages and their tests, agent runtime/CDK configuration, infrastructure source/policies/tests, contracts, integration tests, necessary local build/validation scripts, and selected product/submission documentation. The allowlist is encoded in the script, not inferred from every file under the repository.

Generated empty `.gitkeep` markers preserve `tests/fixtures` and `tests/integration`, which the workspace validator requires. Native Android/iOS projects are intentionally regenerated by Expo from the source configuration; their current build outputs and signing material are not exported.

## Excluded categories

- `.git` and all Git history; `.devpost-hackathon-state.json`, AGENTS/agent memory and editor state.
- `.secrets`, local environment files, `google-services.json`, local SDK properties, private keys, certificates and signing stores.
- Private task records, operational logs, mail/device captures, screenshots/video recordings and raw diagnostic outputs.
- `node_modules`, Python environments/caches, Expo/Gradle caches, Pods, coverage and generated deployment packages.
- APK/AAB/IPA, ZIP/TAR archives, native build binaries and generated Android/iOS trees.
- Live `services/agent/agentcore/aws-targets.json`, old deployment manifests, personal learner notes and historical build logs.
- Files outside the explicit allowlist, unexpected symlinks and unrecognized binary files.

Named product image/font assets and the reviewed architecture PNG are permitted source assets. They are not mail/device captures. Space Mono retains its original metadata and the [SIL OFL 1.1 notice](../../apps/mobile/assets/fonts/LICENSE-SpaceMono.txt); the release allowlist now includes that notice. Non-secret public app/deployment identifiers in selected configuration are not credentials and are not silently rewritten.

## Commands

Run from the repository root with Python 3.12; the script uses only the standard library. The default does not copy source:

```sh
python3 scripts/prepare_source_export.py --self-test
python3 scripts/prepare_source_export.py \
  --reviewed-findings artifacts/submission/source-preview.reviewed-findings.json
```

After the source freeze and review, materialize exactly that manifest:

```sh
python3 scripts/prepare_source_export.py --export \
  --expected-manifest artifacts/submission/source-preview.manifest.json \
  --reviewed-findings artifacts/submission/source-preview.reviewed-findings.json
```

The export directory is `artifacts/submission/source-preview`. The adjacent `source-preview.manifest.json` records every selected path, byte length, SHA-256, executable flag and source/generated origin. `source-preview.sha256` is the plain checksum manifest. The manifest's `source_copied` flag distinguishes a review from a completed materialization. These generated reports stay outside the source export.

The destination is never intentionally replaced. For a refreshed document/build checkpoint, use a fresh output name, generate its manifest first and then export it:

```sh
python3 scripts/prepare_source_export.py \
  --output artifacts/submission/source-preview-final \
  --reviewed-findings artifacts/submission/source-preview.reviewed-findings.json
python3 scripts/prepare_source_export.py --export \
  --output artifacts/submission/source-preview-final \
  --expected-manifest artifacts/submission/source-preview-final.manifest.json \
  --reviewed-findings artifacts/submission/source-preview.reviewed-findings.json
```

If a reviewed test file changed, the old review is rejected even when its path/line still matches. Reinspect that finding and regenerate the reviewed-finding metadata; do not disable scanning. Missing required source, unexpected symlinks/binaries, a changed snapshot or an unreviewed credential pattern also stops materialization. Every copied file is rehashed, and the source is checked again before the export is finalized.

That narrow product fix and final APK/access/document updates are outside this snapshot, so a fresh named export is required after the next freeze. Do not present this directory as the final corrected release.

Twenty pattern matches were reviewed as synthetic test material: 16 descriptive test Expo tokens, two explicit test-secret literals, one sequential synthetic AWS access key and one JWT with a literal non-cryptographic test signature. They exercise registration, redaction or transport boundaries. Their value-free review file contains only path, line, type and that exact file's SHA-256. No matched value or source snippet is included in the manifest or this document. No likely live credential was identified by this bounded scan.

Synthetic script checks cover the allowlist/exclusions, hash-verified copy, empty-directory preservation, stale manifests, symlinks, value-free credential blocking and hash-bound reviewed findings. The script has no network/Git/dependency/publication operations. The current source freeze includes the coordinator's recorded backend/mobile changes; this export does not rerun product tests or certify the final APK. Public download/access, final English copy/live results and submission links may still change, so generate a fresh named export after their document updates.

Credential-pattern checks are a targeted aid, not proof that every secret format is detected. Named PNG/font assets were included by exact path; this check does not inspect arbitrary screenshots or media. Non-secret public configuration identifiers remain in the source. The live AWS target file is excluded; a new operator must configure the intended deployment and supply the documented ignored Firebase/environment files.

A clean export does not cleanse the existing repository's history. No Git history was included in the isolated export. This review authorizes neither publication nor any remote write.

## Historical release boundary

A separate read-only check reviewed the locally available `refs/remotes/origin/main` and `refs/heads/main`. The remote-tracking ref contains one initial commit; local main contains that commit plus 61 local-only commits. The initial commit already includes four internal task/profile documents outside the source-only release scope. Local history additionally contains internal records and unreviewed native captures. Removing these files in a new tip commit would leave their ancestor blobs accessible.

The bounded scan covered 647 reachable UTF-8 text blobs (11,308,546 bytes); none matched the selected credential patterns. Thirty binary blobs were not visually inspected. This result does not make the internal documents/captures suitable for publication. No fetch was performed, so the remote-tracking ref is a local snapshot, not a fresh assertion about the server's current refs. Detailed value-free commit/blob/path evidence is retained locally outside the public export.

**Recommended release base: a new repository with fresh history containing only the final reviewed source export.** Preserve the existing private repository and its local history. Neither existing main commit is an appropriate ancestor for a strictly source-only public release. No force push, history rewrite, commit, push or visibility change was performed or authorized by this check.
