# QuietPilot Build Checklist

## Build Preferences

- **Planning ownership:** Codex designs and sequences the plan; the participant reviews visible outcomes at the locked pauses.
- **Build mode:** Autonomous. `$build-project` executes the checklist in order and does not re-ask ordinary implementation choices.
- **Comprehension checks:** N/A during routine implementation. Explain architecture or tradeoffs when a pause, risk, or user question makes it useful.
- **Git:** Private repository setup and the GPG-signed initial commit `67c61fe` are complete. Do not create additional commits, push, change visibility, publish, or create a PR unless the participant explicitly asks for that exact operation. Any later commit must be GPG-signed.
- **Verification:** Required. A task is complete only with the listed command, live API readback, or real-device observation. Connector mocks are UI/test fixtures, not integration proof.
- **Check-in cadence:** Balanced. Send concise updates at major milestones and before any approval-gated external action; do not stop for ordinary coding decisions.
- **Task sizing:** Each item targets a 15–30 minute active implementation slice. Tool downloads, cloud provisioning, OAuth review and provider propagation time are tracked separately rather than hidden in the estimate.

## Locked Verification Pauses

1. **Mobile UI mockup visual pause:** after the development build, the simulated login and two-area navigation render on the Galaxy S23 Ultra.
2. **Frontend quality pause:** after real-state `진행`, grouped `새 제안`, approval and Case detail screens exist. The participant decides whether the visual quality is acceptable.
3. **Google side-effect pause:** immediately before the first real Calendar/Tasks mutation.
4. **SmartThings command pause:** immediately before any real device command. Read-only inventory does not authorize control.

## Frontend Ownership Boundary

- Codex owns the first complete frontend implementation and its functional tests.
- The participant's visual judgment is authoritative; automated checks cannot mark visual quality accepted.
- If the frontend misses the participant's bar, only `apps/mobile/app`, `apps/mobile/src/components`, feature presentation code and theme tokens are eligible for another-model replacement or redesign.
- API contracts, authentication, AWS infrastructure, AgentCore, connector implementations, policy, state machines and verification remain Codex-owned.
- A frontend handoff, if requested, includes screen/state inventory, design tokens, typed API mocks and run/verify commands. It excludes credentials, external OAuth tokens and cloud secrets.

## Wow Moment

A real Gmail signal or a direct user request becomes the same explainable Case; QuietPilot compresses the work into one exact approval, performs a real Calendar/Tasks action, reads the result back, and shows the verified timeline. SmartThings capability discovery and a separately approved command extend the same contract rather than appearing as a disconnected IoT demo.

## Completion Rules

- Work in dependency order and stop only at the four locked pauses, an external authorization blocker, a destructive/high-impact action, or a failed proof predicate.
- **Credit-wait mode:** local code, tests, Android builds, CDK synthesis and mock-model agent tests may proceed. `aws login`, CDK deployment, AgentCore deployment, Bedrock inference and other AWS usage require verified promotional/free-tier credit or a fresh explicit personal-spend approval.
- A successful HTTP acceptance is not completion when readback is required.
- If a task fails, classify the failed axis, repair that axis and rerun its listed verification before moving on.
- Do not mark a later task complete because a fixture resembles its expected output.
- The final Devpost handoff prepares materials only; actual submission remains a separate approval-gated command.
